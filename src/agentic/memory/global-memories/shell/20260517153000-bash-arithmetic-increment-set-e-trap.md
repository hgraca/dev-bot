In bash with `set -euo pipefail`, `((VAR++))` is an arithmetic expression that evaluates to the _old_ value of VAR. When VAR is 0, the expression evaluates to 0 (falsy), which bash treats as exit code 1 — causing the script to abort silently. Use `VAR=$((VAR+1))` instead, which is always a successful assignment. Affects any counter starting at zero: pass/fail counters, loop indices, retry counts.

In bash with `set -euo pipefail`, `((VAR++))` is an arithmetic command that returns exit code 1 when the expression evaluates to 0 (i.e. when VAR is 0 before increment). This causes the script to abort silently after the first iteration of a counter loop. Use `VAR=$((VAR+1))` instead — it is an assignment, always exits 0. Same applies to `((FAIL++))`, `((PASS++))`, or any counter starting at 0. Discovered in a Bun test runner script where only the first test ran before the script exited.
