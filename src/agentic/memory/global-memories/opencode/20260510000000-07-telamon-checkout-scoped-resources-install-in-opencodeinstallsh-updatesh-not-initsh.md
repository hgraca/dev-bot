## DevBot-checkout-scoped resources install in opencode/install.sh + update.sh, not init.sh

Resources that live under `<devbot-root>/` and are **shared by every project that consumes devbot** (e.g. `src/instructions/tools/node_modules/` for `@opencode-ai/plugin`) MUST be installed in `src/<module>/install.sh` (one-time on `make install`) and refreshed in `src/<module>/update.sh` (on `make update`/`devbot update`) — NOT in `src/<module>/init.sh`. The `init.sh` script runs **per-project** (`make init PROJ=<path>`) and should only do per-project wiring (symlinks into `<PROJ>/.opencode/`, writing `<PROJ>/.ai/devbot/devbot.jsonc`, etc.). Putting devbot-scoped installs in `init.sh` works incidentally on first init but creates three problems: (a) it conflates two lifecycle scopes (per-checkout vs per-project), making it unclear what gets reinstalled when; (b) version bumps in the devbot-scoped `package.json` won't propagate to existing checkouts on `devbot update`, because `init.sh` doesn't re-run unless you re-init each project; (c) the install runs N times (once per project init) instead of once, even though the artifact is shared. Pattern: when a resource is under `<devbot-root>/` and consumed by every project, its install lives in `install.sh`, its refresh lives in `update.sh`, and `init.sh` only warns if the prerequisite is missing (pointing the user at `make install` / `make update`). Discovered 2026-05-10 while wiring opencode custom tools: first cut put `bun install` for `@opencode-ai/plugin` in `opencode/init.sh`; corrected to live in `opencode/install.sh` + `opencode/update.sh` with init.sh emitting a warn-only guard. Reference: commit `1cfec66 refactor(tools): scope @opencode-ai/plugin install to devbot checkout, not per-project`. When to apply: every new dependency installed under `<devbot-root>/`.
