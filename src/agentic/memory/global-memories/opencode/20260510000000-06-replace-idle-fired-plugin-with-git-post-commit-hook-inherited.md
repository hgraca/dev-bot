## Replace idle-fired plugin with git post-commit hook + inherited `$OPENCODE_SESSION_ID`

When an in-process plugin's job is "do work after the agent finishes a meaningful unit of work", consider replacing the `session.idle` event hook with a git **post-commit** hook driven by `$OPENCODE_SESSION_ID`. The idle event has three sharp edges that the commit boundary doesn't: (a) it fires on **every** quiet moment, including mid-workflow pauses, requiring lock files + last-message tag checks + watermarks just to suppress duplicates (see [[gotchas]] L1225+ on triple-firing remember-session); (b) plugin closures are loaded once at session start, so editing prompt text requires a restart (see [[gotchas]] L1245); (c) cross-plugin coordination via filesystem flags (e.g. SME's stall-flag read by remember-session) couples plugins through invisible filesystem state. The commit-boundary alternative is structurally simpler: a commit IS the unit of completed work; hooks run once per commit; hook scripts are re-read every invocation (no closure-staleness restart problem). The session-targeting trick: opencode's `session-id-export.js` plugin sets `process.env.OPENCODE_SESSION_ID` on every `tool.execute.before`, so any `bash` tool invocation — including `git commit` — inherits it; `git commit` then propagates the env to its hooks, where the runner script reads `$OPENCODE_SESSION_ID` and invokes `opencode run --session "$OPENCODE_SESSION_ID" ...` to target the originating session by ID (NOT `--continue`, which would target the most-recently-active session globally and risk polluting an unrelated session). When the env var is unset (manual commit from a normal terminal), the hook exits silently — a deliberate trade-off: terminal commits get no capture rather than a wrong-session capture. Implemented for `remember-session` 2026-05-10: deleted `src/instructions/plugins/remember-session.js`, removed it from `opencode.dist.jsonc`, rewrote `src/git-hook-remember-session/remember-session-hook-runner.sh` to read `$OPENCODE_SESSION_ID` and skip when unset. The `session-id-export.js` plugin becomes a structural prerequisite — it MUST stay enabled and be listed BEFORE any plugin/hook that depends on the env var. When to apply: any in-process plugin whose trigger is "after meaningful work" rather than "on every event" — capture/snapshot/export/index plugins are prime candidates. Cross-ref [[ADRs]] M-ARCH-034 (no shared module between plugins; here we eliminate the coupling entirely by moving one side out of process) and [[gotchas]] (`session-id-export` as load-order prerequisite). Layout: `src/instructions/tools/<name>/<name>.ts` (the tool definition exported via `tool({ description, args, execute })` from `@opencode-ai/plugin`) and `src/instructions/tools/<name>/<name>.py` (the unchanged script). The wrapper resolves the script path with `path.join(context.worktree, ".opencode/tools/devbot/<name>/<name>.py")` because tools live behind the `.opencode/tools/devbot` symlink that mirrors the existing `.opencode/{skills,plugins,agents,commands}/devbot` convention — add the symlink in `src/opencode/init.sh` alongside the others (commit during conversion of `format-md`, 2026-05-10). Why split TS+script instead of porting the logic to TS: (a) the script remains independently runnable on the CLI and in pipe mode, (b) existing pytest/bash tests keep working with only a path update, (c) the TS layer stays trivial — no logic duplication, no test surface to maintain. Wrapper conventions: use `.nothrow().quiet()` on `Bun.$` so non-zero exit doesn't crash the agent; surface `stderr` and `exitCode` in the returned string so the LLM can react; describe the tool clearly enough that the LLM picks it without needing the command file to spell out arguments. Update callers: replace shell-invocation prose in skill files (e.g. `documentation-rules`, `plan_story`) with "use the `<name>` tool" — the LLM resolves the tool by name, no path needed. The slash command (`src/instructions/commands/<name>/<name>.md`) becomes a one-liner that instructs the agent to call the tool with `$1`. When to apply: any time a script is being invoked by the LLM via `bash` and the call surface is stable enough to warrant a typed args schema — the tool form gives Zod validation, discoverability in the tool list, and saves tokens vs spelling out shell paths in every prompt. Cross-ref [[ADRs]] for the `tools/devbot` symlink convention and [[memories]] for the single-source-of-truth principle (script logic stays in the script, not duplicated in TS).
