When a `src/tools/<name>/` dir exists solely to call `opencode.upsert_plugin` (i.e. its install.sh just adds a `.opencode/plugins/devbot/<name>.js` line to `storage/opencode.jsonc`), inline the entry directly in the `plugin` array of `src/tools/opencode/opencode.dist.jsonc` (the template copied to `storage/opencode.jsonc` on install) and remove the tool dir + its entry in `bin/install.sh`'s `POST_DOCKER_APPS`. The plugin JS itself stays at `src/plugins/<name>.js` and is exposed to opencode via the existing `.opencode/plugins/devbot -> src/plugins/` symlink. See [[gotchas]] for the historical reason these wrapper dirs existed. Applied to: agent-communication, diff-context, remember-session.

When a `src/tools/<name>/install.sh` script's only meaningful action is `opencode.upsert_plugin ".opencode/plugins/devbot/<name>.js"`, the tool dir adds zero value over a direct entry in `src/tools/opencode/opencode.dist.jsonc` (the template that becomes `storage/opencode.jsonc` on install). The tool dir creates four kinds of overhead: (1) an entry in `bin/install.sh` `POST_DOCKER_APPS` array; (2) `timed_run` overhead during install; (3) a placeholder `init.sh` (often a `skip` no-op); (4) cognitive load — readers must open the tool dir to discover it does nothing. Pattern: declare plugin entries directly in the dist template, do NOT create a tool dir whose sole purpose is to register the plugin. Discovered while inlining `agent-communication`: the install script just called `opencode.upsert_plugin` and the init script was a `skip` no-op. The diff-context and remember-session plugins follow the same pattern (their entries already in the dist template) — their tool dirs were similarly redundant and slated for deletion in the same reorg. When to apply: every new opencode plugin (skip the tool dir) and during reorg sweeps (delete redundant tool dirs).
