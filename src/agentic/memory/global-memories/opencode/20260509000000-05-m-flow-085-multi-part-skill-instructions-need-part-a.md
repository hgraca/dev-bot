## M-FLOW-085: Multi-part SKILL instructions need Part A / Part B sub-headings + per-part verification gate, not flowing prose

improve-planning SKILL Step 6 originally read "append to the summary table … per-iteration narrative below the table" as a single flowing paragraph listing two MUST-do parts. During iter-10 ledger update I half-executed it: appended the per-iteration narrative twice (once via `edit`, once via heredoc, creating a duplicate `## Iteration 10` section) but never added the table row at the top of the file. The user had to point out twice that iter-10 was missing — first I corrected the duplicate narrative (still missing the row), then they specified "the table at the top". The defect was structurally invisible because both parts were prose-coordinated by "and" rather than sub-headed. Fix: split into explicit `#### Part A — Append a row to the summary table at the top` + `#### Part B — Append a per-iteration narrative section below the table` sub-headings, plus a `Verification gate` sub-section with two grep-count checks (`grep -c "^| ${n} "` MUST return 1; `grep -c "^## Iteration ${n}$"` MUST return 1). Step is NOT complete until both checks return 1. Committed as `a2051c8`.
When a SKILL step's instructions list ≥2 MUST-do output artefacts in flowing prose (joined by "and", "as well as", "below the …"), the structural commitment to do BOTH is invisible at consumption time — the agent reads it as one task and silently picks one. The forcing-function shape that fixes this at instruction-design level is: (a) split into Part A / Part B / … sub-headings making each part a top-level visual unit, (b) add a "Verification gate" sub-section with one mechanical check per part (grep count, file existence, line count, etc.), (c) state explicitly that the step is NOT complete until all checks pass. This is M-FLOW-083 (knowledge ≠ consultation; bridge with forcing-functions) applied at _instruction-design_ level rather than _agent-runtime_ level — the artefact whose absence is detectable here is the missing grep-count match, written into the SKILL itself as a precondition for "step done". Generalises: any SKILL step whose body lists multiple output artefacts joined by prose conjunctions is a candidate for this restructuring. Diagnostic signal at SKILL-review time: count the imperatives ("append", "write", "create", "update") in the step body — if ≥2 and they target distinct artefacts/locations, sub-head them and add per-part verification.
