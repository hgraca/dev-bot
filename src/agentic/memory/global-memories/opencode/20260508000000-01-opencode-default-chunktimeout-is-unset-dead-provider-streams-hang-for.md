## opencode default `chunkTimeout` is unset — dead provider streams hang for the full request `timeout`

opencode's `provider.<name>.options.timeout` is the **whole-request** ceiling (default 300_000 ms = 5 min). Without `chunkTimeout`, a streaming response that goes silent mid-flight (LLM provider crashed, network hung, upstream proxy dropped) waits the full `timeout` window before opencode aborts and surfaces `MidStreamFallbackError: APIConnectionError ... An error occurred during generation.` Net effect: the agent appears frozen for ~5 min, then dies, and any error-driven recovery (e.g. an `event: session.error` plugin) only runs after that delay. Fix: set `chunkTimeout: 300000` (5 min) on the provider — opencode aborts the request when no streamed chunk arrives in that window, surfacing the error fast enough for auto-recovery to be useful but tolerating Opus extended-thinking pauses (which regularly exceed 60s). **Do not use 60s** for Claude on github-copilot — false positives are common because Claude's `/v1/messages` shim batches SSE frames in bursts (upstream opencode #25172) and extended-thinking can legitimately go silent for 60-90s. Initially set to 60000 (commit `63c27fc`); raised to 300000 (commit `abfcda4`) after observing repeated false-positive `SSE read timed out` errors during Opus thinking. Upstream opencode PR #18264/#18275 disable `chunkTimeout` entirely for the same reason; we keep a ceiling because the auto-recover plugin needs _some_ timeout to fire on actually-dead streams. Configured for `github-copilot` in `src/tools/opencode/opencode.dist.jsonc` and `storage/opencode.jsonc`. When adding a new provider that streams, set both `timeout` (loose ceiling, e.g. 600s) and `chunkTimeout` (5 min for Claude, lower for non-thinking models). Confirmed via opencode docs (`https://opencode.ai/docs/config#models`) and upstream issues #17578, #25172. See [[patterns]] for the auto-recover plugin pattern that depends on this, and [[ADRs]] for the dist-vs-storage config split.
