## M-FLOW-084: Generalise gate predicates from "labelled severity" to "every finding" — narrow fixes leak one tier down

improve-planning iter-10. Iter-9 P1 tightened the FINAL-promotion gate to require zero unmet _preconditions_ (findings the critic explicitly marks as preconditions for [FINISHED]). Iter-10 R2 (confirming review) returned `APPROVED` with one new MINOR finding: PLAN-ARCH lines 515–516 declared two ports at `src/Core/Port/SpeciesDataProvider.php` but the directory tree (lines 113–116) and PSR-4 (line 159) place them under `Port/PokeApi/`. Critic flagged it with an explicit "What would make me comfortable" recovery criterion. Architect did not fix it. Orchestrator promoted to FINAL anyway. Iter-9 P1 didn't fire because the finding was MINOR-not-precondition. Same defect class as iter-9 N9.1, one severity tier down. Compounded structural gap: the workflow as executed treats `verdict: APPROVED` as terminal even when new findings exist — there is no architect cycle between confirming review and FINAL. Fix (iter-10 P1): generalised FINAL-gate now requires every finding (any severity — BLOCKER/WARNING/MINOR/SUGGESTION) to have either a fix entry or an explicit dispensation in the Review Response section. Preconditions still strict (no dispensation allowed). Added bounded confirming-review architect cycle in `plan_story` SKILL Step 4 — APPROVED with new findings triggers exactly one architect pass before FINAL, no extra critic round.
When a gate fix scopes to a specific severity tier or finding category to address an observed defect, expect the same defect class to re-emerge one tier down within 1-2 iterations. The pattern: fix BLOCKER-handling → next defect is in WARNING; fix preconditions → next defect is in MINOR. The narrow scope feels safe (less risk of breaking working flows) but creates a "leak channel" at the next tier. Stronger default: generalise the gate predicate to "every finding has either a fix or a documented dispensation" with severity-specific escape hatches (e.g. preconditions cannot be dispensed). This costs at most one extra architect cycle per round of unresolved findings — proportional to defect prevalence, which is the desired property. Companion mechanism: the dispensation entry creates an explicit audit trail for ignored findings, replacing silent drops with named decisions. Generalises beyond planning: any "block on X" gate where X is a typed category should be reformulated as "address each instance of X-or-equivalent" with the typed category as a strict subset.
