## Opencode custom-tool: thin TS wrapper delegating to a colocated script

When converting a CLI script (Python, Bash, etc.) into an opencode custom tool per https://opencode.ai/docs/custom-tools, keep the script intact and add a thin TypeScript wrapper next to it that uses `Bun.$` to invoke it. **Wiring requirements (confirmed via `GET /experimental/tools/ids` on `opencode serve`):** (1) Tool `.ts` files MUST be flat files directly under `.opencode/tools/<name>.ts` — nested subdirs are NOT discovered, so the `<sub>/devbot → src/instructions/<sub>` directory-symlink convention used for skills/plugins/agents/commands does NOT work for tools. (2) `@opencode-ai/plugin` resolves from the file's **real path** (Bun walks up from the resolved symlink target), so `node_modules` must live next to the source — install once at `src/instructions/tools/package.json` with `@opencode-ai/plugin` matching `.opencode/package.json` version. (3) In the `.ts` wrapper, resolve sibling scripts via `path.join(import.meta.dir, "<script>")` — `import.meta.dir` reports the real directory and works through the flat symlink. (4) `init.sh` must (a) `bun install` in `src/instructions/tools/` if `node_modules` is missing, and (b) enumerate `src/instructions/tools/*/<name>.ts` and create per-file flat symlinks `.opencode/tools/<name>.ts`. Verification gate: `curl http://127.0.0.1:<port>/experimental/tools/ids | grep <tool-name>` on a running `opencode serve` — the tool MUST appear, otherwise registration silently failed (`opencode debug agent` shows the agent's allowed-tool filter, NOT the registry). Reference implementation: `src/instructions/tools/format-md/{format-md.py,format-md.ts}` + `src/instructions/tools/package.json` + `src/opencode/init.sh` step 5.
