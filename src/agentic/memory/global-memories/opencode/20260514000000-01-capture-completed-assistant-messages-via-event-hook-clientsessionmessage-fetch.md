## Capture completed assistant messages via `event` hook + `client.session.message()` fetch

The `chat.message` hook in opencode v1.14.50 fires **only for user messages** — `output.message.role` is always `"user"` and `output.parts` is the user's submission. To capture the assistant side of an exchange from inside a plugin, listen for the generic `event` hook filtered to `event.type === "message.updated"` with `event.properties.info.role === "assistant"` AND `event.properties.info.time?.completed` set as a completion gate (streaming intermediate updates have only `time.created`). The event payload only carries metadata (the `Message` info object); to get the actual `parts` (text, tool calls, file refs), call `await client.session.message({ path: { id: sessionID, messageID } })` which returns `{ data: { info, parts } }`. The `client` is destructured from the plugin factory's `PluginInput`. Two essential safeguards: (a) **dedup via module-level `Set<messageID>`** because `message.updated` may fire more than once even after completion (metadata refreshes); (b) **fetch-failure fallback** — wrap the client call in try/catch and write a metadata-only log on error rather than dropping the event silently. Implemented in `src/instructions/plugins/llm-logger.js` (commit `37fb3b8`) alongside the existing `chat.message` hook for users — same `writeMessageLog` helper serves both. Reference patterns: `agent-communication.js` (event hook + client destructuring at line 220, 243-245), `tool-stats.js` (graceful `{data}` destructuring at lines 118-119). When to apply: any plugin that needs to observe completed assistant outputs (logging, analytics, side-channel notifications). Cross-ref [[gotchas]] "Opencode v1.14.50 plugin loader treats every named export as plugin factory" — the file MUST still export only the factory; the second hook lives on the same returned object.
