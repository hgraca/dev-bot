## Auto-recovery from transient mid-stream provider errors via `session.error` plugin

The `session.error` opencode event fires when a session halts due to provider failure (e.g. `MidStreamFallbackError`, `APIConnectionError`, `OpenAIException`, `ECONNRESET`, 502/503/504, "overloaded"). A plugin can listen on this event, match the error message against a transient-error regex, and inject a synthetic recovery prompt via `client.session.prompt()` so the agent resumes without user interaction. Implementation in `src/plugins/auto-recover.js` (commit `63c27fc`). Pattern shape is the same as `remember-session.js` (idle) and `agent-communication.js` (missing markers): worktree-scoped lock + per-session attempt counter + synthetic-prompt tag (`[DevBot-AutoRecover]`) — reuse the three-layer guard from L109. Differences specific to error recovery: (a) max-attempts ceiling MUST be lower (3 vs 10+) because legitimately broken sessions should surface to the human, not loop forever; (b) exponential cooldown (5s → 10s → 20s) between attempts so we don't slam a flapping provider; (c) error-message regex MUST be conservative — only match known-transient classes, leave non-transient errors (auth, OOM, syntax) untouched so the human sees them; (d) plugin is **useless without `chunkTimeout` set on the provider** — see [[gotchas]] (chunkTimeout default unset) — because otherwise the dead stream hangs 5 min before `session.error` even fires, and the recovery feels manual anyway. Tunable via `auto_recover.max_attempts` in `.devbot.jsonc`. Plugin must be wired into BOTH `src/tools/opencode/opencode.dist.jsonc` and `storage/opencode.jsonc` per L1117 / L1123. When to apply: any time you're tempted to tell the user "retry your prompt after a transient error" — automate it instead.
