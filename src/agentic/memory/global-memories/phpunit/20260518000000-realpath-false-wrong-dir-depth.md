When a test file uses `__DIR__ . '/../../...'` to build a path to a fixture directory, `realpath()` silently returns `false` if the number of `../` segments is off by even one. The subsequent `file_get_contents(false)` call then throws `TypeError: Argument #1 ($filename) must be of type string, false given`. This is easy to introduce when test files are moved deeper in the directory tree or when copy-pasting constants across tests at different depths. Always count the directory levels from `__DIR__` to the target manually, or use a helper that asserts the resolved path is not `false` before passing it to `file_get_contents`.

When test fixture files are loaded via `realpath(__DIR__ . '/../../.../path/to/fixture')`, a single missing `../` causes `realpath()` to silently return `false`. Passing `false` to `file_get_contents()` then throws `TypeError: Argument #1 ($filename) must be of type string, false given` — with no indication that the path itself is wrong. To diagnose: count the directory depth of the test file from the repo root and verify the number of `../` segments matches. To prevent: use `__DIR__ . '/relative/path'` without `realpath()` and let PHP throw a clear "failed to open stream" error, or assert `is_file($path)` before reading. The `realpath()` wrapper hides the bad path entirely.
