Paste this prompt into DevBot (or any LLM coding agent) in a PHP/Laravel project to replicate the OpenTelemetry integration from the hotels-api commit `6260d0a` (ARC-761) and get-e/core (ARC-760). Recipe covers: Composer packages (`open-telemetry/exporter-otlp`, `open-telemetry/opentelemetry-auto-laravel`, `open-telemetry/sdk`, `php-http/guzzle7-adapter`, `tbachert/spi` plug-in registration); OTEL_* env vars per environment (local/dev disabled, staging/prod enabled); Docker: install `opentelemetry-1.2.1` PECL extension in Dockerfiles, forward OTEL_* env vars to PHP-FPM via `env[...]` directives in `www.conf`, pass vars in docker-compose with defaults; verify with `php -m | grep opentelemetry`. The `opentelemetry-auto-laravel` package provides zero-config auto-instrumentation for HTTP requests, DB queries, and cache operations. PHP-FPM does NOT inherit env vars from shell by default — explicit `env[...]` directives in `www.conf` are required. `php-http/guzzle7-adapter` bridges PSR-18 to Guzzle for OTLP export. `tbachert/spi` enables service discovery of instrumentation hooks.

Recipe: (1) Add composer packages: `open-telemetry/exporter-otlp ^1.4`, `open-telemetry/opentelemetry-auto-laravel ^1.7`, `open-telemetry/sdk ^1.14`, `php-http/guzzle7-adapter ^1.1`; add `tbachert/spi` to `config.allow-plugins`. (2) Set OTEL env vars in all env files: `OTEL_PHP_AUTOLOAD_ENABLED` (false for dev/test, true for staging/prod), `OTEL_TRACES_EXPORTER=otlp`, `OTEL_SERVICE_NAME=<project>`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`, `OTEL_EXPORTER_OTLP_ENDPOINT=<collector>`. (3) In Dockerfiles: pecl install `opentelemetry-1.2.1`, enable extension, and forward OTEL_* env vars to PHP-FPM via `env[...]` directives in `www.conf` (needed because PHP-FPM's `clear_env=yes` clears environment). (4) In docker-compose: pass OTEL_* vars to the app service. (5) For test env: add `OTEL_PHP_DISABLED_INSTRUMENTATIONS=all` and `OTEL_SDK_DISABLED=true` to prevent ParaTest worker crashes from unconditionally-loaded auto-laravel hooks.
