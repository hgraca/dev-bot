# Audit 51/52 fix session: harness wiring + memory tooling

Two devbot audits (opencode + claudecode fixtures, tests/test-project) ran
against the mdctx engine-swap branch. All FAILs/NOTEs were addressed:

- **claudecode skills gate bypass (FAIL)**: `_link_claude_skills_flat()` walked
  the unconditional `storage/external-agentic-modules` vendor mirror, so
  DISABLED modules' (react/svelte families) skills were flattened into
  `.claude/skills` and fully loadable. Fix: walk the gated `.agents/skills`
  tree — one symlink per WIRED external module — skipping real dirs (devbot/
  wrapper, graphify-style tool dirs) whose skills the dev-bot module walk
  already covers. Regression test in `skills_flat_tests.bats`.
- **opencode harness log unreadable (NOTE)**: `_reconcile_external_directory`
  (opencode init.sh) also ensures `${HOME}/.local/share/opencode/log/**` is
  allowed, so MCP "server unavailable" failures are readable in-band. The
  early-return now no-ops only when deny-first + /tmp/** + log allow are all
  present.
- **format hooks rewrite signal**: on-hooks.ts logs `file.edited hooks rewrote
  <file>` when file.edited hooks change content between user edits (sig
  before/after) — evidence for the opencode fuzzy-edit × async-format splice
  corruption, which is opencode-side and only mitigable in-repo by re-reading
  before a follow-up edit (DevBot profile rule added).
- **search-memories**: format_json entries are now `{file, body}` objects and
  markdown adds a `_File:` line (provenance); mdctx project-store hits get a
  2× score boost over the global store so small project vaults aren't buried.
- **devbot help** prints the current project (cwd walk-up for
  .devbot.project.jsonc) and relabels the install as "Install root".
- **codebase-memory** cold start is now documented loudly (nothing primes the
  index; first `index_repository` required) with known limits (root-too-broad
  guard, group-writable daemon warn).
