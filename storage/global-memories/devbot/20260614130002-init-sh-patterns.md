## init.sh Module Patterns

13 modules have `init.sh` files, following 6 distinct patterns:

**Pattern A — Plugin registration (5 modules)**: agent-communication, auto-recover, guards, format-json, format-md. All follow identical template: resolve `PROJECT_DIR`, call `_upsert_opencode_plugin "${CONFIG}" "${PLUGIN}"` with the plugin path. Each registers a single opencode lifecycle plugin.

**Pattern B — Config copy + gitignore (1 module)**: repomix. Copies `repomix.config.dist.json` (if not exists), then adds `.gitignore` section.

**Pattern C — Config copy with sed substitution (1 module)**: codebase-index. Copies `codebase-index.dist.json` to `.opencode/codebase-index.json`, substituting `__OLLAMA_API_URL__` placeholder with the local Ollama endpoint.

**Pattern D — Vault scaffold + plugins + gitignore + symlinks (1 module)**: memory. Scaffolds `.ai/devbot/memory/` vault from template, registers two plugins (file-edited reindex, session-idle remember-session), updates `.gitignore`.

**Pattern E — Full application CLI setup (2 modules)**: graphify (installs git hooks, MCP wrapper, initial knowledge graph build), qmd (registers QMD collections, builds index+embeddings).

**Pattern F — External module wiring (1 module)**: external-modules. Reads `.devbot.jsonc` modules config, symlinks external module paths into `.opencode/`, sets up storage structure.

The shared `_upsert_opencode_plugin` function from `_shared/functions.sh` is the most reused helper across init scripts.
