## FILTER_FLAG_NO_PRIV_RANGE misses IPv4-mapped IPv6 — detect mapped addresses via `inet_pton` bytes

When validating that a resolved IP is public (SSRF guard before cURL), `filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE)` does **not** reject IPv4-mapped IPv6 forms: `::ffff:127.0.0.1` and its hex spelling `::ffff:7f00:1` both pass as "public" IPv6 and would then be pinned for the request, reaching loopback/link-local services. A dotted-tail heuristic (`str_contains($ip, '.')`) misses the hex form. Detect mapped addresses structurally: `inet_pton` a 16-byte value whose first 10 bytes are zero and bytes 10–11 are `0xff 0xff`, then validate the embedded IPv4 (bytes 12–15, `inet_ntop`-ed) with the IPv4 range flags.
