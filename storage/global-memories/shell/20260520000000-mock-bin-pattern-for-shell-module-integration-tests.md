To test shell scripts that call external tools (docker, uv, git) without requiring real binaries, create a `mock-bin/` directory per test case, write tiny wrapper scripts there (e.g. `docker` that exits 0 or 1 on demand), and prepend it to `PATH` before invoking the script under test. Each test case gets its own isolated temp directory (e.g. under `.ai/devbot/memory/thinking/test-<name>-<PID>/`) with its own `DEVBOT_ROOT`, `SECRETS_DIR`, and `mock-bin/`. Teardown removes the temp dir. This pattern lets you test all code paths (success, failure, fallthrough) without network access or real tool installation, and is used in `tests/litellm/test-install.sh` as the canonical reference.

When writing integration tests for shell module scripts (`install.sh`, `init.sh`, `update.sh`) that call external tools like `docker` or `uv`, create a `mock-bin/` directory per test case, write tiny wrapper scripts there (e.g. `mock-bin/docker` that exits 0 or 1 on demand), and prepend it to `PATH` before invoking the script under test. Each test case gets its own isolated temp directory (e.g. under `.ai/devbot/memory/thinking/test-<module>-<PID>/`) with its own `DEVBOT_ROOT`, `SECRETS_DIR`, and `FUNCTIONS_PATH` overrides. This lets the full script run against real DevBot functions while controlling every external command's exit code. Clean up the temp dir in a `teardown` function registered with `trap teardown EXIT`. See `tests/litellm/test-install.sh` for a complete reference implementation.
