When `git commit` fails with `error: invalid object <sha> for '<file>'` and `git fsck` shows `missing blob <sha>`, the index entry for that file references a blob that no longer exists in the object store. Fix: run `git rm --cached <file>` to drop the corrupt index entry, then `git add <file>` to re-hash from the working tree and create a fresh blob. The working tree file is intact — only the index pointer is broken. This can affect multiple files in the same staging area; repeat for each file named in the `invalid object` error. Do not use `git add -A` or `git add .` — re-stage only the affected files to avoid accidentally staging unintended changes.

When `git add` or `git commit` fails with `fatal: unable to read <sha>` / `missing blob <sha>`, the index has a stale reference to a blob that no longer exists in the object store. Fix: run `git checkout HEAD -- <file>` for each affected file — this rewrites the index entry to point at the HEAD-committed blob, clearing the corrupt reference. The working tree file is overwritten with the HEAD version (any uncommitted changes to that file are lost). After the reset, `git status` should show clean and commits should succeed. Caused in this session by a failed `git add` that partially wrote an index entry. See [[project/20260519130000-shared-constants-belong-in-port-not-infrastructure.md]].
