Running bare `bun test` from the devbot repo root walks INTO the vendored opencode source tree at `storage/opencode-src/packages/opencode/test/server/...` and executes opencode's own test suite, which fails noisily (SQLite "no such table: project", drizzle-orm errors, HttpApi 500s, fiber interruptions, command timeouts). These failures are 100% unrelated to devbot's own test suite and create false negatives that mask real issues. **Always scope to the repo's own test folder**: `bun test tests/` or specific files like `bun test tests/plugins/agent-communication.test.ts`. The repo has no `bunfig.toml` to constrain test discovery, so the default crawl picks up everything.
