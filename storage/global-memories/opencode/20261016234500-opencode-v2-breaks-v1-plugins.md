## OpenCode 2 replaces the plugin API and moves terminal config to a global file

OpenCode 2 (2.0.0 published 2026-09-11) has three intentional breaking changes, and the first two are fatal to any V1 plugin: **V1 plugin implementations do not run in V2** — moving a file or renaming a config entry is not enough. A V1 plugin returns one object of tools and hooks; a V2 plugin default-exports `Plugin.define({ id, setup(ctx) })` from `@opencode/plugin` and registers each hook on the domain that owns it: `event` → `ctx.event.subscribe()` (async for-await, cleaned up by the function `setup` returns), `tool.execute.before/after(input, output)` → `ctx.tool.hook("execute.before"/"execute.after", event)` with ONE mutable `event`, `chat.params` → `ctx.session.hook("context", e)` writing `e.options.*`, `shell.env` → `ctx.shell.hook("create.before", e)`, `tool` map → `ctx.tool.transform` with JSON Schema input. The server API changed contracts too (use `@opencode/client`), and terminal configuration moved from layered `tui.json(c)` to one **global** `~/.config/opencode/cli.json` — project-local client config is not migrated, so a TUI plugin now ships via `exports["./tui"]` from `@opencode/plugin/tui` rather than a per-project file. Config renames V2 accepts but normalizes in memory: `permission` (object) → `permissions` (ordered array, last match wins, `bash`→`shell`, `task`→`subagent`, `write`/`patch`→`edit`), `agent`→`agents` (`prompt`→`system`, `disable`→`disabled`, `variant` joins the model as `provider/model#variant`), `provider`→`providers` (`npm`→`package` with an `aisdk:` prefix), `plugin`→`plugins` (tuple → `{package, options}`), `mcp`→`mcp.servers` with `enabled` inverted to `disabled`. Two behavioural traps: `external_directory` is **allowed by default** in V2 (add an explicit `ask` rule to keep V1 behaviour), and `lsp` config is accepted but **inert** — V2 runs no language servers and emits no diagnostics. `AGENTS.md` is the only instruction file discovered (the `CLAUDE.md` fallback is gone). One package can serve both: export the V2 `setup()` beside a V1 `server()` object, but the dual shape needs a **1.18.29+** host.
