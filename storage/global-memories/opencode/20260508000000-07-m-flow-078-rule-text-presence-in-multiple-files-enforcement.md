## M-FLOW-078: Rule-text presence in multiple files ≠ enforcement — prose-only gates need a verification artifact

improve-planning iter-7 P1 — the `summary.md` required-artifact gate existed in BOTH `src/agents/devbot.md` (Planning Stage Responsibilities) AND `src/skills/workflow/plan_story/SKILL.md` Step 5. Yet iter-7 still skipped writing `summary.md`. Quality-report iter-7 §5 framed the fix as "move/dedupe the rule"; verification of the actual files showed both copies already existed and the framing was wrong. The real defect was that both copies were prose ("output it to the human user", "summary must be written") with no forced execution path — no tool call, no checklist artifact, nothing the orchestrator had to physically produce. Compare `@tester` gate, which works because the rule mandates a `read` tool call against a concrete artifact path: presence of the artifact + verifying tool call cannot be narrated past. Fix: introduce `<issue-folder>/planning-complete.md` as a closing-checklist artifact listing every required artifact as `[x]` only after a verifying `read`/`ls` tool call. The orchestrator must write that file before transitioning stages — the file's existence is the gate, not the prose.
When a process rule fails despite being correctly placed in the canonical file(s), do not assume the fix is "place it more prominently" or "duplicate it elsewhere". Check whether the rule has an **enforcement mechanism** distinct from its **textual presence**. Prose rules ("MUST write X", "MUST output Y") rely on the agent reading, remembering, and executing — three steps that all fail under load. Concrete-write closing-checklists ("write `path/to/checklist.md` with a verifying tool call per row") replace those three steps with one observable filesystem artifact whose absence is detectable by the next stage. The check at design time: "if I delete every word of this rule's prose but keep the artifact requirement, would the workflow still enforce the gate?" If yes, the artifact is doing the work and the prose is documentation. If no, the rule is prose-only and will regress under model pressure. Generalises beyond planning: any "MUST output X to the user" rule that doesn't bind X to a filesystem path or tool call is fragile.
