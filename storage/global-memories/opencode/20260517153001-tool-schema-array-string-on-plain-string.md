When an opencode custom tool declares an arg as `tool.schema.array(tool.schema.string())` and the LLM calls it with a plain string (e.g. `paths: "src"`), the `@opencode-ai/plugin` framework crashes with `undefined is not an object (evaluating 'p.split')` before `execute()` is reached — any normalization guard inside `execute()` never runs. Fix: declare the schema as `tool.schema.union([tool.schema.array(tool.schema.string()), tool.schema.string()])` so the framework accepts both forms, then normalize to array inside `execute()`. Applies to any tool arg that logically accepts one-or-many values.
