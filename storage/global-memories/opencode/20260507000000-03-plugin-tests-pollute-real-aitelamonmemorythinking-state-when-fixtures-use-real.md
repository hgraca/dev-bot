## Plugin tests pollute real `.ai/devbot/memory/thinking/` state when fixtures use real session IDs

`tests/plugins/agent-communication.test.ts` and `tests/plugins/remember-session.test.ts` create plugin instances with `directory: makeTmpDir()` so MOST state goes to a tmpdir — but the plugin's counter/lock/stall-flag paths use `worktreeSlug(worktree, directory)` which derives the slug from `basename(worktree || directory)`. When `worktree: undefined` is passed AND the test fixture session IDs collide with what the test suite uses across runs, the counter file at `.ai/devbot/memory/thinking/.agent-communication-counter-<slug>.json` may persist across runs IF the slug derives from the actual project basename rather than the tmpdir basename. Reality observed this session: after running the test suite, `.ai/devbot/memory/thinking/.agent-communication-counter-devbot.json` accumulated entries for `sess-task3-001`, `sess-r4-wrongshape`, etc. — proving production code wrote to the REAL vault, not the tmpdir. Once any session entry hit `attempts: 2` (max ceiling), subsequent test runs for the SAME session ID would short-circuit nudge delivery → `client.session.prompt` not called → 5 spurious test failures (H.8, H.9, R.4, R.6, R.7). **Symptom signature**: tests pass on a clean state but fail on the second run — exactly the trust-breakdown pattern in L1037. **Workaround**: `rm .ai/devbot/memory/thinking/.agent-communication-counter-*.json` before re-running tests to confirm a "real" failure vs. state leak. **Real fix needed**: tests must override `worktreeSlug` resolution OR use a unique slug per test (e.g., pass `worktree: tmpDir`) so plugin state lands in tmpdir not real vault. Cross-ref L1037 (developer self-reports unreliable), L1027 (real vault is symlinked git repo). See [[memories]].
