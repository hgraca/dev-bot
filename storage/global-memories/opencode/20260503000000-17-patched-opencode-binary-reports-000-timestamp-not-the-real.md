Building opencode from source produces a binary that reports `0.0.0--<build-timestamp>` because `Script.version` reads from `package.json` (which has `0.0.0` — actual version is injected at release time from git tags). This causes any version-check logic comparing against the latest tag to always think it's outdated, triggering unnecessary reinstalls. Fix: pass the target version explicitly to `apply-patches.sh` as an argument; never rely on `opencode --version` for patched builds.

After building opencode from source with patches, `opencode --version` reports `0.0.0--<build-timestamp>` instead of the tag version (e.g. `1.14.33`). This breaks version-comparison logic that checks against git tags. Fix: don't rely on `opencode --version` for patched builds — use the patch state file (`storage/opencode-patch-state.json`) which records the actual version + SHA.
