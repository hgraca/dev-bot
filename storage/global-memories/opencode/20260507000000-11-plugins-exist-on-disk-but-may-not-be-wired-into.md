`src/plugins/compaction-save.js` (writes `compaction.md` breadcrumbs to `.ai/devbot/memory/work/active/<task>/` on `experimental.session.compacting`, and injects task title into post-compaction summary) existed in the repo for an unknown period but was **never listed** in either `src/tools/opencode/opencode.dist.jsonc` or `storage/opencode.jsonc`, so opencode never loaded it and no breadcrumbs were ever written. Symptom: silent — no error, no marker file, agents resuming after compaction had no signal that compaction had occurred. Root cause: writing a plugin file is not the same as enabling it; opencode only loads plugins explicitly enumerated in the `plugin` array. Fix (commit `cb4c7d5`): added `.opencode/plugins/devbot/compaction-save.js` to the array in both `opencode.dist.jsonc` (committed) and `storage/opencode.jsonc` (host-local, gitignored). Generalises: when adding any new plugin, check both config files; when investigating "why isn't plugin X firing", grep the plugin arrays first before debugging the plugin code. `remember-session.js` is **also** missing from both arrays despite heavy use in our memory protocol — flagged for follow-up. Discovery: `src/plugins/compaction-save.js` was fully implemented (hooks `experimental.session.compacting`, writes `compaction.md` breadcrumbs to active work items, injects task title into post-compaction summary) but had silently never run, because it was missing from the `plugin` array in **both** `src/tools/opencode/opencode.dist.jsonc` (default config baked into init) and the host-local `storage/opencode.jsonc`. Symptom is invisible: no error, no warning, no log line — the plugin just doesn't fire on the event it subscribes to, and downstream consumers (e.g. `recall-active-task` reading the breadcrumb) silently degrade. Same failure mode applies today to `remember-session.js` (heavily referenced in memory protocol) and `active-work-context.js` — neither is in either config's plugin list. Rule: **a plugin file under `src/plugins/` is dead code until added to BOTH config files** — the dist file (so fresh installs get it) and the storage file (so the running session picks it up). When adding a new plugin, audit both configs; when debugging "plugin doesn't seem to work", check the `plugin` array first before reading source. Fix in commit `cb4c7d5` for compaction-save.
