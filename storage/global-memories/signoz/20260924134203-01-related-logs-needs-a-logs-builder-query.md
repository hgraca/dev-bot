## Alert deep links come from `related_logs`, which needs a logs builder query in the rule

SigNoz attaches a `related_logs` annotation (and `related_traces`) to every alert it evaluates — a pre-built Logs Explorer URL carrying the window and the filters — but the logs variant is only assembled when the rule contains a **logs builder query**. `ThresholdRule.prepareParamsForLogs` scans the rule's queries for one whose spec unmarshals to `QueryBuilderQuery[LogAggregation]`; a rule whose only query is `clickhouse_sql` gets no link at all, so a channel template's `{{ if .Annotations.related_logs }}` silently renders nothing. A *disabled* builder query is enough — the scan ignores `disabled` and the querier skips it — so a ClickHouse-SQL rule can carry a throwaway `builder_query` (`signal: logs`, `disabled: true`) holding the severity filter and the `service.name`/`deployment.environment` group-by purely to drive the link. The window is `[eval_time − evalWindow, eval_time]` in **milliseconds** (widen `evaluation.spec.evalWindow` to widen the link), the host comes from `SIGNOZ_ALERTMANAGER_SIGNOZ_EXTERNAL__URL` (it falls back to `http://localhost:8080` when unset), and the generated filter is the builder query's expression plus every alert label not in `PredefinedAlertLabels` (`threshold.name`, `severity`, `lastSeen` — everything else, including the group-by attributes, is appended as `key='value'`). The window is therefore always trailing and can never be centred: Alertmanager's template functions have no duration constructor (`date`, `tz`, `since`, `humanizeDuration` exist; `duration` and `parseDuration` do not, and the rule's own annotations expose only `{{$value}}`, `{{$threshold}}` and the group-by attributes), so `StartsAt ± N` cannot be computed in the channel template. Render the result as a Slack hyperlink, `<url|text>` — Slack does not render markdown `[text](url)` and prints it literally.
