## The clickable title of a SigNoz Slack notification is `title_link`, which opens the alert rule page — a dashboard link needs an annotation the channel actually renders

Reported as "the notification links to the alert definition, so I cannot see what is wrong". The title is the only clickable element in a default three-line body, and `scripts/setup-alerts.sh` writes `title_link: "{{ template \"slack.default.titlelink\" . }}"` for every channel, which resolves to the rule's own page (`/alerts/overview?ruleId=<id>`). Two independent things are therefore missing when a notification has no useful link: the rule carries no dashboard URL, and the channel's `text` template never renders one. The fix is both halves — an `annotations.link` on the rule (a full Slack hyperlink string `<https://…|Label>`, not a bare URL) **and** a guarded `{{ if .Annotations.link }}{{ .Annotations.link }}\n{{ end }}` line in the channel `text`, exactly like `Slack: alerts` / `Slack: anomaly-alerts`. Guarding matters when a channel is shared by several rules: an unannotated rule then prints nothing instead of an empty line. Templating the deep link per notification works because `{{$<grouped-attribute>}}` placeholders are substituted into the annotation *after* the URL is percent-encoded, so `variables=%7B%22environment%22%3A%22{{$deployment.environment}}%22%2C%22service%22%3A%5B%22{{$service.name}}%22%5D%7D` renders as valid encoded JSON as long as the substituted label values contain no characters needing encoding (service names and environments are plain tokens; anything with a space or `&` would break it). Prefer this over retargeting `title_link`: that field is one template per channel, cannot be per-rule without a script change, and was not verified to be honoured when overridden.
